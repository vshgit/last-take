# Разработка и сборка

## Среда

- Игровой движок: Godot 4.5.1 в исходной сборке. Повторная проверка восстановления использует установленный Godot 4.6.3, Linux.
- Язык: GDScript; графические эффекты — Godot shader language.
- Редактируемый персонаж: `ArtSource/character-v10/cinemaniac_v10.blend`; для его изменения нужен Blender. Готовые GLB уже в `Source/assets/`, Blender не нужен для обычного запуска игры.
- Существующие Python-генераторы используют Pillow/NumPy, отдельные скрипты — Blender и локальный Piper/ONNX. Точные импорты и внешние пути смотреть в конкретном скрипте. Эти зависимости не нужны для запуска готового проекта.
- Речь уже сгенерирована. Модель Piper ru_RU-denis-medium и внешние инструменты не считаются включёнными, пока не найдены отдельно. Не обещать полную воспроизводимость генерации голосов из одного репозитория.

## Проверки

Команды из корня репозитория (в Windows имя/путь исполняемого Godot может отличаться):

```sh
python3 tools/verify_recovery.py
godot --headless --editor --path Source --import
godot --headless --path Source --audio-driver Dummy -- --qa
```

Дождаться завершения импорта перед запуском QA. Игровая проверка должна завершиться и показать все шесть маркеров: `V1_CHECKS_PASSED`, `SOUNDS_CHECKS_PASSED`, `GESTURE_REPLAYS_PASSED`, `GESTURE_INPUT_CHECKS_PASSED`, `V09_CHECKS_PASSED`, `GAMEPLAY_CHECKS_PASSED`. Точные имена сверять с текущими исходниками; в отчёте фиксировать реальные найденные маркеры. Проверять также `SCRIPT ERROR`, `Assertion failed`, ошибки загрузки и exit code. Тайм-аут не считать успехом.

Исторические проверки 0.10 входят в общий QA вместе с 1.0. Headless-проверки не оценивают внешний вид, удобство управления и слышимость на реальном устройстве. Для затронутых игровых изменений нужна ручная проверка. Сообщения освобождения ресурсов при выходе перечислять отдельно.

`tools/verify_recovery.py` проверяет побайтовую сохранность исходного состояния; после намеренных игровых правок расхождения с базой ожидаемы и не являются автоматическим основанием откатить правку. Историю сохраняет Git; старый манифест не переписывать под новое поведение.

## Экспорт Windows

Установить соответствующие версии движка и export templates. В `Source/export_presets.cfg` сохранён профиль `Windows Desktop` с x86_64 и встроенным PCK. Стандартный путь в старом профиле — `../LastTake.exe`; лучше задавать отдельный каталог сборки явно:

```sh
mkdir -p builds
godot --headless --path Source --export-release "Windows Desktop" ../builds/LastTake.exe
```

Проверить фактический выходной путь. Рядом с EXE можно разместить `Launch-Compatibility.cmd` из корня и сведения о версии. Нативно запустить на Windows, проверить вступление, четыре типа вопросов, паузу, ошибки, победу/поражение, звук и перезапуск. Сборку упаковать отдельно, связав с commit и версией движка.

## Другие платформы

Общий проект является отправной точкой. Профили macOS/Web/Android/iOS пока не добавлены и сборки не проверены. Web требует отдельной оценки рендерера и браузерных ограничений; мобильные устройства — интерфейса и ввода. Не менять Forward+ автоматически ради экспорта. macOS и iOS — разные цели.

## Контент и генераторы

Код отделяет `voice_id` от `audio`. При замене аудио сохранить ID вопроса, обновить путь `audio`, импортировать ресурс и проверить цикл, паузу и остановку. Карточки и слайды уже готовы; генераторы могут перезаписать их. Не запускать `Recovery/` и `Source/tools/` без чтения кода и отдельной задачи. У ряда исторических скриптов сохранены абсолютные пути прежней среды.

В Git сохраняются код, данные, готовые ассеты, исходные модели, `.import` и `.uid`. Кэш `.godot/`, EXE/PCK и локальные credentials исключены. При импорте другой версией движка следить за изменениями `.import` и не смешивать их молча с игровой правкой.
